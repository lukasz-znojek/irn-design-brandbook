# Presentation template

## Purpose
- Define the standard structure and visual rules for IRIN presentation decks.
- Help decks feel premium, deliberate, and easy to follow in live and async settings.
- Align slide craft with `../identity/typography-system.md`, `../identity/color-system.md`, and `../docs/03_quality-bar.md`.
- Reduce reinvention across proposals, product walk-throughs, workshops, and case-study decks.
- Keep client-facing material calm and authoritative rather than sales-heavy.

## When to use
- Use for client presentations, proposals, workshops, and strategic readouts.
- Use for founder talks when IRIN appears as the presenting brand.
- Use for internal decks that may later be externalized.
- Use when converting research, design rationale, or product strategy into slides.
- Use when building case-study narratives for business development.
- Use when a partner needs an editable deck built on the IRIN system.
- Use alongside `../applications/internal-docs-style.md` when a deck originates from a written proposal.
- Use alongside `../templates/creative-brief-template.md` for project kickoff decks.
- Do not use as a substitute for dense documentation when a memo would communicate better.

## Inputs
- Presentation objective and audience list.
- Speaking context: live pitch, board update, workshop, or async review.
- Core narrative with beginning, middle, and close.
- Approved facts, metrics, screenshots, and diagrams.
- Required legal or confidentiality statements.
- Color and typography references from the identity docs.
- Speaker notes or facilitation notes if the deck is presented live.
- Time limit so slide count and pacing stay realistic.
- Accessibility needs such as minimum text sizes and contrast checks.

## Outputs
- A structured deck with the slide types defined in this document.
- Consistent master layouts with grid, type scale, and spacing locked.
- Speaker notes where context is needed beyond visible slide content.
- Export-ready presentation and PDF versions when required.
- A filename with audience, topic, and date.
- A review checklist outcome using `../templates/design-qa-checklist.md`.
- If data slides are included, a source log for charts and key figures.

## Owner
- Primary owner: Brand design lead or presentation designer.
- Narrative owner: Strategy lead, founder, or account lead.
- Data accuracy owner: Analyst or source document owner.
- Final approver: Meeting owner or founder for external decks.
- Accessibility owner: Designer exporting the final file.

## Quality criteria
### Recommended deck structure
| Slide type | Purpose | Typical count | Notes |
| --- | --- | --- | --- |
| Cover | Set the frame and audience context | 1 | Quiet, simple, confident |
| Agenda | Show path through the conversation | 1 | Optional for short readouts |
| Section divider | Reset attention between chapters | 2-6 | One thought per divider |
| Content slide | Explain a point with text and image | 4-20 | Main working slide type |
| Data slide | Show evidence, chart, or metric | 0-10 | Must include source note |
| Closing | Summarize, invite next step, or thank | 1 | Never end abruptly |

### Slide grid
- Default canvas: 16:9 widescreen.
- Outer margin: 64 px on desktop presentation software masters.
- Content columns: 12-column grid for flexible text and image splits.
- Column gutter: 24 px.
- Baseline rhythm: 8 px units.
- Header band: reserve upper zone for slide title and short context line.
- Footer band: use only when needed for confidentiality, page numbers, or source notes.
- White space is functional; do not fill every open area.

### Type sizes for decks
| Element | Suggested size | Notes |
| --- | --- | --- |
| Cover title | 34-44 pt | Keep to two lines where possible |
| Cover subtitle | 16-20 pt | One supporting sentence max |
| Section divider title | 28-36 pt | Strong and spare |
| Content title | 22-28 pt | Clear statement, not topic label only |
| Body text | 14-18 pt | Stay readable at room distance |
| Data label | 12-16 pt | Never drop below legibility threshold |
| Quote emphasis | 24-32 pt | Use with ample margins |
| Footnote/source | 10-12 pt | Only for source or legal detail |

### Color use on light vs dark slides
- Light slides are the default for dense information and diagrams.
- Dark slides are best for covers, section dividers, and short emotional resets.
- On light slides, use near-black text instead of pure black when the palette allows.
- On dark slides, use warm off-white text and avoid low-contrast muted grays.
- Limit accent color to one emphasis system per deck chapter.
- Do not alternate light and dark slides without narrative reason.
- Charts on dark slides require thicker lines and simplified legends.
- Buttons or CTA-like devices in decks should be subtle, not web-like.

### Slide-type rules
- Cover: title, audience, date, and optional short descriptor only.
- Agenda: three to six bullets; never a wall of sub-bullets.
- Section divider: one thesis phrase or chapter label.
- Content slide: one core idea, one supporting visual, one proof line.
- Data slide: one key takeaway in the title so the chart does not speak alone.
- Closing: summarize next steps, contact route, or decision request.
- Case-study decks may add a results slide before closing.
- Workshop decks may add exercise slides using the same grid and type system.

### Do and don't for client decks
- Do lead with clarity and sequence.
- Do name the implication of a chart directly in the title.
- Do use screenshots or diagrams with purposeful callouts.
- Do trim text until each slide can be understood in under ten seconds.
- Do keep motion minimal if animation is used at all.
- Don't turn slides into memos by shrinking text.
- Don't decorate divider slides with empty brand gestures.
- Don't use sales clichés, exclamation points, or false urgency.
- Don't rely on color alone to encode meaning.
- Don't present unfinished thinking as polished certainty.

### Production checks
- Verify every slide aligns to the master grid.
- Check font embedding or package the deck with safe export settings.
- Confirm speaker notes do not contradict visible content.
- Spell-check client names, product names, and dates.
- Ensure every external metric includes a source or source appendix.
- Review the deck in full-screen mode before delivery.

## Example (IRIN)
- Scenario: IRIN is presenting a product design and engineering engagement proposal.
- Cover slide title: "Precision, made visible." 
- Cover subtitle: "A focused design-and-engineering partner for ambitious growth-stage teams." 
- Agenda slide: context, opportunity, working model, scope, timeline, next steps.
- Section divider example: "Where ambiguity slows delivery." 
- Content slide example title: "The current workflow hides decision debt." 
- Layout: left column insight, right column annotated flow diagram.
- Data slide example title: "Three approval loops are adding avoidable latency." 
- Source note: derived from stakeholder interviews and workflow mapping dated August 2026.
- Closing slide: concise next-step options and founder contact details.
- Visual behavior: mostly light slides, dark section dividers, one muted accent color.
- Tone: expert, direct, and unhurried.

## Common failure modes
- Opening with branding instead of context.
- Packing six ideas into one content slide.
- Letting charts appear without a takeaway statement.
- Switching type sizes ad hoc to fit content.
- Using dark backgrounds for data-heavy slides that need fine detail.
- Treating agenda slides as obligatory even when the deck is five slides long.
- Overusing mockups that distract from the actual recommendation.
- Forgetting that a deck may be read asynchronously without the presenter.

## How to avoid generic output
- Write slide titles as claims, not categories.
- Anchor the story in the audience's real operating tension.
- Use IRIN language about structure, clarity, craft, and precision.
- Make each slide earn its place in the sequence.
- Replace empty inspiration language with evidence or implication.
- Use the grid to create calm, not to force decorative symmetry.
- Review against `../docs/03_quality-bar.md` before final export.
- If the same deck style could sell any agency, strip it back and sharpen the narrative.
